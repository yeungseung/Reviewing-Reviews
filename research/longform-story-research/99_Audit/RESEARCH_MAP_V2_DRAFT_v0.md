# 0. Why v2 needs a different map

The original 86-item map mixes five different kinds of questions:

1. **Mechanism questions**  
   What does attention, memory, appraisal, curiosity, causal inference, etc. actually do?

2. **Bridge questions**  
   Does a mechanism established in another domain transfer to longform narrative/video?

3. **Platform questions**  
   Does a behavior affect CTR, retention, continuation, subscription, rewatch, search, etc.?

4. **Design-tool questions**  
   Is a worksheet, taxonomy, checklist, map, or module useful and reliable?

5. **Synthesis questions**  
   Does the full Story Engine explain or improve content design?

Treating all five as ordinary literature-review questions caused repeated errors:
- domain transfer was mistaken for direct evidence
- psychological mechanisms were converted into YouTube KPIs
- design heuristics were presented as empirical laws
- exact timing constants were invented from qualitative theory
- taxonomies were labeled "exhaustive" without taxonomy validation

Research Map v2 separates these layers.

# 16. Candidate minimal engine state model

The audit increasingly points toward a smaller set of dynamic state variables:

```
EVIDENCE / EVENT
       ↓
CAUSAL + GOAL MODEL
       ↓
ACTIVE QUESTION / EXPECTATION
       ↓
NEW INFORMATION
       ↓
STATE / BELIEF / MEANING UPDATE
       ↓
APPRAISAL
       ↓
EMOTION + JUDGMENT
       ↓
RELEVANCE / VALUE / STAKES
       ↓
NEXT QUESTION / ACTION / EXPECTATION
       ↓
RESOLUTION / REFRAME / OPEN END
```

Cross-cutting constraints:

```
TRUST / PROVENANCE
PROCESSING CAPACITY
VISUAL / MULTIMODAL IMPLEMENTATION
PLATFORM / PACKAGING CONTRACT
```

Product layer:

```
DESIGN TOOLS
→ SCRIPT
→ ANNOTATION
→ AUDIENCE DATA
→ UPDATE ENGINE PRIORS
```

This is currently the strongest candidate architecture produced by the audit.

It remains provisional until independent-source precision research and actual content validation are completed.
