## 2. How to read the matrix

- **Completed / Legacy planned** measures only coverage of the original 257-Theme plan after mapping it into v2 Tracks. It is not a recommendation to finish every remaining legacy Theme.
- **Source refs** counts distinct SRC IDs cited inside each Report, summed across Themes.
- **Unique SRC IDs** removes repeated citation of the same ID inside a Track.
- **Dedup source families** collapses duplicate registrations by DOI or normalized title.
- **Families / Theme** is a rough breadth indicator, not an evidence-quality score.
- **Reused families ≥2 Themes** exposes dependence on the same original literature across multiple Themes.
- **Audit-flagged** counts only problems already recorded in the Audit Log. It is a lower bound, not an error rate.

## 5. Major coverage conclusions

### 5.1 The corpus is concentrated in D / J / C
The largest completed areas are:
- D Appraisal / Emotion / Value
- J Design Architecture & Instruments
- C Uncertainty / Curiosity / Narrative Expectation

This means the archive is **not balanced around the needs of a production-ready Story Engine**. It is much heavier on emotion, narrative mechanisms, and proposed design structures than on platform evidence and real-world validation.

### 5.2 I and K are structural blind spots
- I Packaging / Platform Contract: **0 completed primary Themes**
- K Empirical Story Engine Validation: **0 completed primary Themes**

These two tracks are where unsupported YouTube/OTT KPIs and exact production constants should have been tested. Their absence helps explain why the corpus repeatedly jumped from psychology to CTR/retention/subscription claims.

### 5.3 J is over-counted if treated as science coverage
J has many completed Themes because the original map repeatedly asked whether a taxonomy, module, checklist, or template was "valid."
That is useful exploratory work, but it should not be counted the same way as mechanism evidence.

Future J work should primarily use:
- corpus coding
- inter-rater reliability
- usability tests
- revision-quality tests
- predictive validity against real content

### 5.4 B / C / F contain the best candidates for mechanism precision research
Current audit indicates:
- B contains causal-model and state-update mechanisms that survive source deduplication
- C contains strong story-specific questions but also the worst construct conflation around "prediction"
- F contains broad capacity/processing evidence but many unsupported timing and density constants

These should be precision-researched before final engine synthesis.

### 5.5 A is under-covered relative to its importance
Only a small part of Trust/Provenance has been completed, while the remaining #60–#63 directly address the exact weaknesses found in the archive.

A should be expanded before further high-confidence synthesis.

## 6. Recommended next move

Do **not** use Theme count as the main priority signal.

For each Track, the next-stage Claude queue should be based on:

```
Priority =
  Story Engine centrality
  × Evidence uncertainty
  × Domain-transfer risk
  × Audit error exposure
  × Missing empirical validation
```

9. **L — final synthesis only after the above**
